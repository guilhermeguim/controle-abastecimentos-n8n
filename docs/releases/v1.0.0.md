# Release v1.0.0

## Data de fechamento

2026-07-20

## Base de comparação

Primeira release pública do projeto.

## Resumo

- Tipo: MAJOR inicial.
- Escopo: publicação da base versionável do workflow n8n.
- Workflow original analisado: `Abastecimentos.json`.
- Workflow público: `workflow/abastecimentos.sanitized.json`.
- Nodes no export original: 24.
- Nodes no export sanitizado: 24.

## Objetivo

Publicar a primeira versão documentada do workflow n8n de controle pessoal de abastecimentos via Telegram, sem expor credenciais, tokens, banco real ou metadados da instância.

## Procedimentos de fechamento executados

- Export original identificado e mantido fora do Git.
- JSON sanitizado gerado a partir do export original.
- Credenciais, IDs de webhook e metadados da instância removidos.
- Schema SQLite mínimo documentado.
- Processo de versionamento documentado.
- Validações locais executadas antes da publicação.

## Principais entregas

- Registro de abastecimentos a partir de mensagens do Telegram.
- Continuação de registros incompletos por estado em `abastecimentos_pendentes`.
- Correção, confirmação e cancelamento de pendências.
- Persistência final em `abastecimentos`.
- Consultas em linguagem natural com agente limitado a uma ferramenta SQLite somente leitura.
- Documentação inicial de importação, segurança e manutenção.

## Mudanças de banco e migração

Esta release inclui apenas o schema inicial em `database/schema.sql`.

Não há dados reais, migração incremental ou carga de exemplo.

## Compatibilidade

- n8n Community Edition.
- Community node `n8n-nodes-sqlite3`.
- Telegram Bot configurado no n8n.
- Credencial Groq configurada no n8n.
- Modelo `openai/gpt-oss-120b`.
- SQLite com as tabelas `abastecimentos` e `abastecimentos_pendentes`.

## Procedimento recomendado de deploy

1. Instalar o community node SQLite no n8n.
2. Criar o banco SQLite privado.
3. Aplicar `database/schema.sql`.
4. Importar `workflow/abastecimentos.sanitized.json`.
5. Configurar credenciais do Telegram, Groq e SQLite.
6. Revisar parâmetros dependentes do ambiente.
7. Testar o fluxo no n8n antes de ativar.

## Smoke test pós-deploy

- Enviar mensagem de novo abastecimento pelo Telegram.
- Confirmar pedido de dado faltante quando a mensagem estiver incompleta.
- Confirmar registro completo.
- Consultar último abastecimento em linguagem natural.
- Cancelar uma pendência de teste.

## Rollback

Volte para a tag estável anterior e importe manualmente o JSON sanitizado correspondente.

Credenciais, banco real, execuções e volumes Docker precisam ser recuperados por backup privado separado.
